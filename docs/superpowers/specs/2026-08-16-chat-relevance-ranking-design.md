# 聊天路径专利相关性排序 + 通配符自适应 — 设计规格

**日期:** 2026-08-16
**状态:** 已批准（用户确认「就用这个设计吧」）
**分支:** feature/agent-react-loop
**范围:** 聊天 ReAct 路径的结果排序与呈现；长任务路径不动

## 背景与问题

聊天路径今天的结果链：搜索工具按日期返回 → 截前 100 展示/摘要 → agent 观察只取前 20（按日期）→ 同一轮多次搜索调用（阶梯紧→松）结果互相覆盖，最后一次为准。无任何相关性排序（长任务路径有 Flash 评分闸门，聊天路径没有——两边质量差距的根因）。

663 命中案例：单概念检索式命中 663 条，按日期取前 50 展示，交付泛化；对比 workbuddy 18 件精选差距大。

改写模型对通配符规则执行不稳定（上次产出引号短语而非 `air dry*` 类变体，紧式检索假性 404）。用户决策：通配符使用按用户问题明确程度自适应判断，判断不清就都试——而非无条件要求。

## 决策记录（用户已确认）

1. **排序机制**：代码侧 Flash 评分（复用长任务闸门 `relevance_gate.py`），不用 agent 自主筛选
2. **跨调用**：同一轮多次搜索合并候选池统一排序
3. **呈现**：Top-N 精选（agent 最终回答列出）+ 整体摘要 + 排序后下载
4. **通配符**：W1 方案——改写 prompt 内概念明确度判断，纯 prompt 改动，无 schema 变化
5. **通用性 D5（硬约束）**：任何模块不得硬编码领域关键词/阈值/分支；prompt 示例跨领域多样；验收用多领域基准

## ① 数据流——候选池合并 + 增量评分

作用域：仅后端（push=2）关键词搜索工具、且结果可被 `build_candidates` 解析（USPTO 形状）。其余工具走原路径，零影响。

在 `sources/agents/react_tools.py` 的 `execute_action` 现有截断处注入排序环节：

1. **候选池**：agent 实例新增 `_search_pool`，每轮对话开始重置（挂在现有 `_pending_raw_items = None` 同一处）。每次搜索返回条目经 `build_candidates` 展平后按 `patent_id` 合并入池——同轮多次调用不再互相覆盖
2. **增量评分**：只对池中未评过分的候选调用 Flash 评分（复用 `relevance_gate.score_candidates` / `apply_scores`；依据用户原始问题；输入标题+申请人+日期，与长任务口径一致）。已有分数不重复评——阶梯 ≤6 次调用、每次 ≤100 新候选 → 每次至多 1 次 Flash 调用
3. **排序**：`relevance_score` 降序；未评到分的沉底但保留（评分失败不丢结果）；池上限 300（与长任务 `MAX_COLLECTED_CANDIDATES` 同值）；同族去重复用 `dedupe_candidates`
4. **输出**：`_pending_raw_items` = 排序后前 100（`MAX_PATENT_LIST_ITEMS` 同值）；观察摘要取排序后前 20 条且带分数；观察文本注明「已按相关度排序、池共 N 条、评分 M 条」

展示管道（`_stream_raw_items`）、下载 artifact（`build_result_artifacts`）、patent_ids 前端传递均不改代码——输入自然变为排序后列表。

## ② 通配符自适应（W1，纯 prompt）

- `sources/long_task/search_query_builder.py` 的 `REWRITE_SYSTEM_PROMPT` 概念抽取步骤加通用判断规则（不带任何领域专属示例词）：
  - 概念为明确专有名词/品牌/具体化合物 → 精确词即可
  - 一般性技术概念 → 词集中必须含词尾通配符变体
  - 判断不清 → 精确词与通配符变体都放入词集
- 「都试」由现有同工具阶梯穷尽纪律（≤6 次）承载，不加新机制
- 现有 prompt 中单一领域专属示例替换为跨领域多样示例，避免锚定单一测试问题
- `format_ladder_guidance`（agent 可见的阶梯指导）加一句通用话术：观察到假性零命中时，可给概念词补词尾通配符变体重试——双保险，弥补「机制对、模型执行不稳」

## ③ Top-N 精选呈现

- `sources/agents/general_agent.py` 纪律指导（阶梯注入处）加通用指令：检索观察带相关度评分时，最终回答先列最相关 Top-N（默认 10，模块常量可调）——每条含申请号+标题+一句相关理由，再给整体摘要
- 现有大列表摘要模式输入即排序后列表，其 prompt 补一句「列表已按相关度排序，开头优先呈现最相关项」
- Excel/CSV 下载自动为排序后内容
- 前端零改动——精选清单由 agent 最终回答的流式文本承载

## ④ 错误处理 / 降级 / 开关

- Flash 评分抛错 → 池内未评分候选保持 API 原序沉底，永不 raise（与长任务闸门口径一致）
- 环境变量 `REACT_RELEVANCE_RANK`（默认开）：置 0 时完整回退今天的按日期截断行为——部署问题一键回滚
- 延迟：每次搜索调用 +1 次 Flash 调用（约 1-2 秒），阶梯穷尽最坏约 +10 秒，可接受

## ⑤ 测试与验收

- 单测（无 provider）：池合并去重、增量评分只评新 id、排序稳定性（未评分沉底）、300 上限、摘要取排序后前 20、观察文本
- 通配符 prompt 文本断言（含「无领域专属示例词」断言）+ 阶梯指导新句
- 全量回归：`PYTHONUTF8=1 python -m pytest tests/ -q --continue-on-collection-errors`，基线 423/26/9 零新增
- 部署后验收：多领域基准（干燥空气/电池热管理/半导体腔温/AR 光学/医疗 AI 五域），每查询切题率≥80%——不按单一测试问题验收

## ⑥ 不改什么（范围护栏）

- 长任务路径不动（已有闸门）
- 每调用仍只取 API 首页；深挖靠 agent 收紧检索式或长任务
- 评分输入仍是标题+申请人+日期（检索响应无摘要字段）
- 前端不动；不加新依赖
