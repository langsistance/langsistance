# copiioai.cn 纯静态官网（公安备案用）

- 日期：2026-09-23（brainstorm 定稿）
- 状态：设计已确认，待实现
- 分支：`feat/weapp`（当前分支；**本工作与 weapp 无关，实现时建议另开分支**）
- 目标：让 `copiioai.cn` **真实地**不构成「具有舆论属性或社会动员能力的信息服务」，从而不需要做安全评估

---

## 1. 背景与依据

### 1.1 问题

公安备案时，备案系统判定服务具有舆论属性或社会动员能力，要求提交安全评估报告。评估涉及 6 项要求，逐项盘点后确认 `copiioai.cn` 当前在提供完整应用（登录 / 对话 / 知识库 / 社区），缺口包括：无真实身份核验、无 IP 与审计日志留存、无内容审核、无举报入口、无配合监管机制。

### 1.2 判定依据

《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》按**功能特征**判定，射程包括：论坛、博客、微博客、聊天室、通讯群组、公众账号、短视频、网络直播、**信息分享**、**小程序**等，或附设相应功能；以及提供公众舆论表达渠道、能发动社会公众从事特定活动的其他服务。

**关键推论**：一个不含用户注册、不含 UGC、不含分享与互动功能的纯静态介绍页，不落入上述射程。因此正确做法不是"把 6 道题答得漂亮"，而是**让网站形态本身不适用**。

### 1.3 三个必须成立的条件

本设计的正确性完全押在这三条上。**任意一条不成立，这个站就从"官网"退化为"静态壳"，性质从程序性违规变为虚假备案。**

| # | 条件 | 本设计如何保证 |
|---|---|---|
| 1 | 整站静态，不能只有首页静态 | 新建**独立 COS 桶**，桶内只有静态文件，`copiioai.cn/app` 等路径**物理上不存在**。不靠配置兜底 |
| 2 | 服务改由别处提供，且别处按规矩办 | 页面引导至 `copiioai.com`（短期）与微信小程序（上线后）。二者各自处理其备案与评估义务 |
| 3 | 以后不能把 `.cn` 再指回应用 | §4 的回滚预案只允许回退到"旧桶"，不允许把 `.cn` 指向应用产物；§6 的验收脚本可回归检测 |

## 3. 页面设计（`frontend/cn-site/`）

### 3.1 技术形态

**手写 HTML，无 npm、无 bundler、无构建步骤**——与现有 `frontend/index/` 同构。

```
frontend/cn-site/              # ← 这个目录整体上传到桶，无例外
├── index.html                 # 单页，CSS 内联，零外部请求
├── privacy-policy.html        # 本站专属
├── robots.txt
├── sitemap.xml
└── assets/                    # logo、favicon（本地文件）

frontend/cn-site-verify.sh     # 验收脚本，见 §6；在站点目录之外，不会被上传
```

**`verify.sh` 刻意放在站点目录之外**：站点目录内只有需要上传的文件，因此任何上传方式（包括手滑的整目录同步）都不可能把开发工具带进桶里，也不可能漏传文件。§6 的 C1 检查依赖这个前提。

### 3.2 内容结构

| 区块 | 内容 |
|---|---|
| 首屏 | 品牌 + 一句话定位 + 入口区（去 `copiioai.com`；小程序码留注释位） |
| 核心能力 | 专利检索、查重、审查历史分析、族分析、报告生成 |
| 数据来源 | USPTO / CNIPA / EPO / JPO |
| 使用方式 | 直接提问、上传文件、粘贴链接、批量任务 |
| 页脚 | 联系方式 · 隐私政策 · ICP 备案号 · 公安备案号 · 版权 |

### 3.3 隐私政策（独立一份）

**不复用** `frontend/nextjs/app/(landing)/privacy-policy/page.tsx`——那份描述的是账号、会话、知识库的数据处理，与一个静态介绍页完全对不上。`cn-site` 这份只需说清两件事：

1. 本站为产品介绍页面，不提供账号功能，不收集个人信息
2. 服务器访问日志会记录来源 IP，用于安全留存，保留不少于 6 个月

### 3.4 语言

**中文单语**。这是给国内监管与国内用户看的站，中文单语审查面最小、维护最省。现有 `frontend/index/index.html` 的 7 语言切换不沿用。

### 3.5 不沿用 `frontend/index/index.html` 的三个原因

该文件是**产品转向专利之前的旧版**（canonical 指向 `copiioai.com`，文案为 "Turn APIs into Conversations"），仅可参考结构：

| 问题 | 证据 | 处理 |
|---|---|---|
| Google Analytics | `index.html:8` preconnect googletagmanager | 移除 |
| YouTube 嵌入 | `index.html:9`、`:174` `youtube.com/embed/WC3b299li7U` | 移除 |
| Unsplash 外链图 | `index.html:10`、`:12`、`:30` | 移除，图片本地化 |
| 调用后端埋点 | `index.html:241-254` `sendBeacon` → `api.copiioai.com/web/page_view` | 移除（**页面只要还在调 API，就不是静态站**） |

## 4. 源站与拓扑改造

### 4.1 已确认的现状（2026-09-23 实测）

| 项 | 实测值 | 证据来源 |
|---|---|---|
| 权威 DNS | `remy.ns.cloudflare.com` | `nslookup -type=CNAME copiioai.cn` |
| 代理 | Cloudflare 在流量路径上 | 响应头 `Server: cloudflare` |
| 边缘节点 | 美国圣何塞 | 响应头 `CF-RAY: ...-SJC` |
| TLS 证书 | Let's Encrypt `CN=copiioai.cn`，90 天有效期 | `openssl s_client` |
| 源站 | 腾讯云 COS | 响应头 `x-cos-request-id` |
| `.cn` 与 `.com` 是否同源 | **是**：两侧 `x-cos-hash-crc64ecma` 完全相同 | 两侧响应头 |

**结论：Cloudflare 同时承担权威 DNS、反向代理、TLS 证书三项职责。** 因此"摘掉 Cloudflare"不是换一个 DNS 服务商那么简单——**证书必须另行解决，否则 `.cn` 将直接失去 HTTPS**。

另注：当前流量经美国节点中转，对境内备案站点不是可接受的稳态。

### 4.2 目标拓扑

```
copiioai.cn → DNSPod（免费版）→ 腾讯云 COS 自定义源站域名（+ SSL 证书托管）
                                      ↓
                                 新 COS 桶（纯静态文件）
```

**为何不经 CDN**：腾讯云 COS 支持「自定义源站域名」并托管 SSL 证书，**无需 CDN** 即可为自有域名提供 HTTPS。这在两方面优于 CDN 方案：

1. **日志直接满足留存要求**——直连 COS 时，COS 访问日志中记录的就是**用户真实 IP**；若走 CDN，COS 侧只剩 CDN 回源 IP，必须另外开通 CDN 访问日志才能拿到真实 IP（§5.1）。少一个环节。
2. **少一个服务**——不引入 CDN 的配置与运维面。

**代价**：无边缘缓存，访问速度取决于客户端到 COS 地域（广州/上海）的直连。对五页静态官网够用；主要代价是跨境访问慢，而本站用户在国内。

**为何裸 CNAME 到 COS 默认域名不可行**：`bucket-appid.cos.<region>.myqcloud.com` 的证书是 `*.cos.<region>.myqcloud.com`，浏览器请求 `https://copiioai.cn` 会**证书不匹配**。绑定自定义源站域名并由 COS 托管证书后，COS 会为该域名下发匹配的证书。当前之所以无此问题，仅因 Cloudflare 代为终止 TLS。

### 4.3 新建 COS 桶

- **地域**：广州或上海
- **权限**：公有读私有写
- **静态网站托管**：默认首页 `index.html`，默认 404 页 `404.html`
- ⚠️ **源站类型必须选「静态网站源站」，不能选「默认源站」**——否则 `index.html` 首页规则与 404 规则不生效，而验收脚本 B1 的十条路径要返回 404 **完全依赖这一设置**（见 §6 与部署清单 D2）

### 4.4 切换顺序（一次性窗口，但把回滚最慢的步骤排在最后）

| # | 步骤 | 出问题时的回滚速度 |
|---|---|---|
| 1 | 新建桶，上传静态文件 | — |
| 2 | 绑定自定义源站域名 + 托管 SSL 证书 | — |
| 3 | 用自定义域名验证站点，跑 `verify.sh` B 组 | — |
| 4 | **提前 24 小时把 `.cn` 的 TTL 调到 60 秒** | — |
| 5 | 记录当前 NS 与全部解析，截图存档 | — |
| 6 | **在 Cloudflare 里把 `.cn` 的 CNAME 改指 COS 存储桶域名** | **秒级** |
| 7 | 验证 `.cn` 站点正确，`verify.sh` B 组全绿 | — |
| 8 | 在 DNSPod 建好全部解析记录（先不切 NS） | — |
| 9 | **切换 NS 到 DNSPod** | **慢**（受 NS 传播期影响） |
| 10 | 验证解析与站点 | — |

**第 6 步与第 9 步刻意拆开**：站点替换（第 6 步）风险最高但回滚最快；DNS 权威迁移（第 9 步）风险低但回滚慢。把慢回滚的那步放在**站点已验证正确之后**，避免两类问题在同一个窗口里互相掩盖。

### 4.5 回滚

| 出问题的步骤 | 回滚动作 | 生效速度 |
|---|---|---|
| 第 6 步之后站点异常 | CNAME 改回旧桶 | 秒级（TTL 已调小） |
| 第 9 步之后解析异常 | NS 切回 Cloudflare | 24–48 小时 |

**回滚边界**：回滚只允许回到旧桶（即恢复原状）。**不得**把 `.cn` 指向任何应用产物或应用入口以"临时救急"——那正是 §1.3 条件 3 禁止的。

## 5. 访问日志留存

依据《网络安全法》第二十一条：网络日志留存不少于 6 个月。这是**静态站也必须满足**的唯一硬合规项。

### 5.1 决策：以 COS 访问日志为留存依据

`.cn` 直连 COS（§4.2，不经 CDN），因此 **COS 访问日志中记录的就是用户真实客户端 IP**，直接作为满足留存义务的日志源——无需再单独开通任何 CDN 日志。

需在 COS 侧开通**日志管理**，把访问日志投递到专用日志桶（§5.2）。注意日志生成有延迟，**验证时不要以"刚访问完没看到记录"判定失败**。

### 5.2 日志配置

- **投递目标**：专用日志桶，不与站点桶混用
- **生命周期规则**：保留 **12 个月**（要求 ≥6 个月，留一倍 buffer），到期自动转归档或删除，避免无限增长
- 日志桶访问权限与站点桶隔离

## 6. 验收标准

**原则：不写"本网站是静态的"这类断言，给出一串能当场跑出结果的检查。**

落成 `frontend/cn-site/verify.sh`，输出逐条 PASS/FAIL。三个用途：备案前留档、将来改动后防回归、网安问起时现场跑。

### A. 本地静态检查（对仓库文件）

| # | 检查 | 通过标准 |
|---|---|---|
| A1 | 无表单与输入 | `grep -E '<form\|<input\|<textarea'` → 零命中 |
| A2 | 无境外依赖 | 提取全部外部域名 → 全部境内，或零外部域名 |
| A3 | 无 API 调用 | `grep -E 'fetch\(\|XMLHttpRequest\|sendBeacon\|api\.copiioai'` → 零命中 |
| A4 | 无应用路由链接 | `/app`、`/login`、`/community`、`/signup` → 零命中 |
| A5 | 备案号占位存在 | 页脚含 ICP / 公安备案号占位节点 |

### B. 线上检查（对 `copiioai.cn`）

| # | 检查 | 通过标准 |
|---|---|---|
| B1 | 应用路径不可达 | `/app` `/login` `/community` `/signup` `/sessions` `/knowledge` → 全部 404 |
| B2 | 首页可达 | `/` → 200，内容与桶内 `index.html` 一致 |
| B3 | 无重定向到应用 | B1 各路径**不得** 302 到 `.com` 应用页 |

B3 易漏——审查人看到的是"这个站把我送进了应用"，与直接提供服务无实质区别。

### C. 基础设施检查（人工，控制台）

| # | 检查 | 通过标准 |
|---|---|---|
| C1 | 桶内文件清单 | 完全等于 `frontend/cn-site/` 内容，无 `_next/`、无应用产物 |
| C2 | 日志桶 | 有访问记录、是真实用户 IP、生命周期 ≥6 个月 |
| C3 | 链路中无 Cloudflare | §7 P1 |

C1 是最强的一条：桶是新建的，**桶里没有应用文件不是"配置成这样"，是物理上不可能有**。

### D. 开发方式

顺序：**先写 `verify.sh`，再写页面**。

| 阶段 | 门槛 |
|---|---|
| 写页面之前 | `verify.sh` 的 A 组可运行，初始必然全红 |
| **上传到桶之前** | **A 组必须全绿**——这是不会把应用产物或境外依赖带进桶的保证 |
| DNS 切换之前 | B 组在**新桶的测试域名**上跑通（此时尚未切 `.cn`） |
| 切换之后 | B 组在 `copiioai.cn` 上全绿 |

注意 B 组依赖线上可达，因此"全绿"分两个时点：**A 组全绿是部署闸门**，B 组全绿是切换闸门。

## 7. 已确认项与遗留待办

### 7.1 已确认（2026-09-23 实测，证据见 §4.1）

| # | 原问题 | 结论 |
|---|---|---|
| P1 | `.cn` 是否经 Cloudflare 前置 | **是**，且 Cloudflare 同时是权威 DNS、反向代理、TLS 证书签发者。方案由"摘除代理"升级为"整体迁出"，见 §4 |
| P2 | CNAME 指向 COS 默认域名还是 CDN | 当前经 Cloudflare 指向 COS。**裸 CNAME 到默认域名会证书不匹配**；改用 COS 自定义源站域名 + 证书托管解决，**无需 CDN**，见 §4.2 |

### 7.2 本次实测引出的新待办

| # | 待办 | 原因 |
|---|---|---|
| N1 | 确认 COS 侧 SSL 证书的续期方式 | 当前证书是 Cloudflare 自动续期的 90 天 Let's Encrypt 证书；迁出后若续期靠人工，会在 90 天后静默失效 |
| N2 | 开通 COS 日志管理，确认日志字段与生成延迟 | §5.1 的留存依据 |
| N3 | 新桶命名与地域 | 需全局唯一（COS 桶名带 APPID 后缀），不阻塞动手 |

## 8. 时序待办

**页脚没有备案号本身就是备案例行检查项**，因此号码填入必须列入待办，避免遗忘。

```
静态站上线
  → ICP 备案获批（取得 ICP 备案号）→ 页脚填入 ICP 号
  → 公安备案获批（取得公安备案号）→ 页脚填入公安号
  → 微信小程序上线 → 首屏加入小程序码区块
```

| # | 待办 | 触发条件 |
|---|---|---|
| T1 | 页脚填入 ICP 备案号 | ICP 备案获批 |
| T2 | 页脚填入公安备案号 | 公安备案获批 |
| T3 | 首屏加入小程序码 | 小程序上线 |

## 9. 护栏：明确不做、不写的内容

以下内容**不得**出现在 `cn-site` 的任何文件中：

| 不写 / 不做 | 原因 |
|---|---|
| 任何表单、输入框 | 构成"收集个人信息"，破坏静态站定性 |
| 知识库 / 社区 / 对话截图 | 会让"无 UGC"的表述失守 |
| 任何指向应用的深链接 | 破坏条件 1 |
| 任何对 `api.*` 的调用（含埋点） | 破坏条件 1；页面只要还在调 API 就不是静态站 |
| GA / YouTube / Unsplash 等境外依赖 | 境内备案站不应引入境外第三方；同时是"个人信息保护"项的证据缺口 |
| 认证徽章（等保 / ISO / SOC 2） | 未持有，与既有护栏一致 |
| "数据不出境""不与任何第三方共享"类表述 | 静态站虽不涉及，但**不得**借此站为整体产品背书 |
