## 10 步切换

第 **6** 步与第 **9** 步刻意拆开：站点替换风险最高但回滚是**秒级**；
DNS 权威迁移风险低但回滚要 **24–48 小时**。
把慢回滚的那步放在站点已验证正确之后，两类问题就不会在同一个窗口里互相掩盖。

- [ ] **1.** 新桶已就绪，五个文件在位
- [ ] **2.** COS 自定义源站域名 + SSL 证书已配好
- [ ] **3.** 已用 hosts 覆盖验证通过（部署清单 D7）；
      或已决定跳过预验、留到第 7 步一并验（回滚是秒级的，可接受）
- [ ] **4.** `.cn` 的 TTL 已降至 60 秒且已生效
- [ ] **5.** 当前 NS 与解析已截图存档
- [ ] **6.** **在 Cloudflare 里把 `.cn` 的 CNAME 改指 COS 存储桶域名**
      ← 站点内容在此刻切换。**这是风险最高的一步，也是回滚最快的一步**

      验证：
      ```bash
      curl -sI https://copiioai.cn/ | head -5      # 应 200
      ./frontend/cn-site-verify.sh https://copiioai.cn
      ```
- [ ] **7.** **B 组必须全绿**（B1 十条路径 404、B2 首页 200 且为本站文件、B2b 隐私政策页 200）。
      未全绿则执行下面的「回滚 A」，**不要继续**

      > 到这一步为止，站点已经是新的、正确的、且 `.cn` 已指向它。
      > 如果想在此收工、改天再切 NS——完全可以。那时站点已是稳态，
      > 第 8–10 步纯粹是收尾。

- [ ] **8.** DNSPod 侧记录已就绪（重复确认，不漏 CNAME 之外的记录）
- [ ] **9.** **切换 NS 到 DNSPod**
- [ ] **10.** 验证：

      ```bash
      nslookup -type=NS copiioai.cn          # 应显示 DNSPod 的 NS
      curl -sI https://copiioai.cn/ | head -5
      ./frontend/cn-site-verify.sh https://copiioai.cn
      ```

      另需确认**证书是新的那张**（不再是 Cloudflare 签发）：
      ```bash
      echo | openssl s_client -connect copiioai.cn:443 -servername copiioai.cn 2>/dev/null | openssl x509 -noout -issuer -dates
      ```

## 回滚

| 出问题的步骤 | 回滚动作 | 生效速度 |
|---|---|---|
| 第 6 步之后站点异常 | **回滚 A**：CNAME 改回旧桶 | 秒级（TTL 已调小） |
| 第 9 步之后解析异常 | **回滚 B**：NS 切回 Cloudflare | **24–48 小时** |

- [ ] **回滚 A**：在 Cloudflare 把 `.cn` 的 CNAME 改回原值，恢复原状
- [ ] **回滚 B**：把 NS 切回原 registrar 的 NS，按切换前截图的记录还原

> ⚠️ **回滚边界**：回滚**只允许回到旧桶**（即恢复原状）。
> **不得**把 `.cn` 指向任何应用产物或应用入口以"临时救急"——
> 那正是设计文档 §1.3 条件 3 禁止的做法，会把"官网"变成"静态壳"。

## 备案号填写细则（T1 / T2）

页脚的两个占位节点在**每个页面**上都有（现在共两个页面：`index.html`、`privacy-policy.html`），
填号时要**逐页填**，不要只填首页——多数属地要求全站每个页面的页脚都展示备案号，
只填首页的话，监管人员打开隐私政策页就看不到。

### T2 特别提醒：公安备案号必须给链接补上可点击的文本

`police-license` 是一个 `<a>` 元素，当前状态是：

```html
<a id="police-license" data-pending="true" href="https://beian.mps.gov.cn/"></a>
```

它**内部是空的**（开始标签与结束标签之间什么都没有）。空元素没有内容，因此：

- 渲染高度是 **0px**——在页面上看不见
- 没有可点区域——**点不动**，尽管 `href` 写得好好的

填入公安备案号时，**必须把号码文本放进标签内部**，而不是只改 `data-pending`：

```html
<a id="police-license" data-pending="false" href="https://beian.mps.gov.cn/">京公网安备 110105020xxxxx 号</a>
```

只把 `data-pending` 改成 `false` 而不补文本，等于把一个 0px 高、点不动的空链接留在线，
既通不过"页脚是否显著展示备案号"的检查，也让 `href` 指向的备案查询入口形同虚设。

顺带确认 `href` 保留 —— 公安备案号按惯例要能点进 `beian.mps.gov.cn` 查到对应记录。

### 两条共同的动作

- [ ] ICP 备案号（T1）：把文本填入 `id="icp-license"` 的 `<span>` 内，`data-pending` 改 `false`
- [ ] 公安备案号（T2）：把文本填入 `id="police-license"` 的 `<a>` 内，`data-pending` 改 `false`，保留 `href`
- [ ] **两个页面都填**（`index.html`、`privacy-policy.html`）
- [ ] 重跑 `./frontend/cn-site-verify.sh` —— 确认 `A5b` 的提醒**完全消失**
      （若只剩一个页面在提醒列表里，说明漏填了那一页）
- [ ] 重新上传改动过的文件到桶里

### 隐私政策的更新日期需要核对

隐私政策页写的是：

> 更新日期：2026 年 9 月 23 日

这个日期是**编写时的日期**，不是实际发布日期。填 T1/T2 时若已晚于该日，
**实际发布日与页面所写的日期就对不上了**——一份自称"9 月 23 日更新"、
但实际是 10 月才上线的隐私政策，在审查时属于可被质疑的陈述。

- [ ] 核对 `privacy-policy.html` 的"更新日期"是否等于**实际对外发布的那一天**
- [ ] 若不等，改成实际发布日；若有内容改动，同理更新
- [ ] 改完重新上传 `privacy-policy.html` 并复跑验收脚本
